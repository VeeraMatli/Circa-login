# App Store preparation

Proposed name: HeartTrail. Subtitle: Find your kind of connection. Promotional text: A little common ground. A meaningful beginning. Meet adults who share your intentions, interests and a thoughtful approach to dating.

Description draft: HeartTrail brings shared intentions into focus. Connection Compass explains common interests and preferences, Conversation Spark offers curated ways to say hello, and the Safe Dating Center keeps privacy and respect close at hand. Discover mutually eligible adults, choose to connect, and chat only after a mutual match. Essential reporting, blocking and safety controls remain free. Optional membership offers additional discovery tools. Product availability depends on the released configuration. No claim of scientifically validated compatibility or guaranteed outcomes.

Keyword draft: dating,relationships,connections,compatibility,interests,chat. Review keyword length, trademark rights and localizations before upload.

Release steps:

1. Enroll the operator in Apple Developer and App Store Connect, register configurable bundle IDs, team and App ID. Enable Apple sign-in and Push, configure APNs key, signing/provisioning and associated developer resources. Never commit signing certificates/P8 keys.
2. Build on macOS with Swift 6/Xcode 16+, run simulator/device XCTest/Swift Testing/XCUITest, accessibility inspector and TestFlight. Archive Release with the actual HTTPS API, correct team/bundle, products and production mock flags false. Use Organizer Validate/Distribute; upload is not automated here.
3. Create one subscription group, monthly Plus/Gold/Elite products and localized descriptions. Suggested planning prices were $9.99/$19.99/$29.99, not prices to hardcode in UI. Choose annual prices separately. Configure server notifications and API keys. Test purchase, pending/decline, restore, renewal, upgrade/downgrade, grace, billing retry, expiration, refund and revoke. Xcode local testing is not a server-verified sandbox transaction. To inspect local StoreKit states, choose HeartTrail.storekit in Edit Scheme → Run → Options. Local API catalog exposes planning product IDs; sync still requires independent verification and will not turn an Xcode-only receipt into a live entitlement. Use the explicitly local /v1/dev/entitlements override only in development.
4. Supply completed legal/privacy/subscription/community/safety policies and live support website. Confirm staffed moderation, age-assurance contracts and launch-jurisdiction review. Resolve every gate in readiness.md.
5. Complete App Privacy disclosures for name, contact info, user ID, purchases, location, sensitive preferences where collected, photos/messages/user content and diagnostics. Reconcile SDK manifests and actual provider processing. No tracking is declared; verify it remains accurate. The included privacy manifest is an engineering draft, not a completed disclosure.
6. Answer age-rating questions honestly for user-generated content, messaging, sexual content controls, dating/adult-only eligibility and moderation. Do not assume an age rating is an adult-assurance system.
7. Screenshots: original onboarding, Connection Compass discovery, mutual match, Conversation Spark chat, safety/privacy and membership terms. Use separately approved synthetic screenshot accounts; never leak real users. Support required iPhone/iPad sizes, Dynamic Type and light/dark modes. Icon source and 1024px asset are included; trademark/design approval remains external.
8. Review notes: explain adults-only eligibility and differentiation, provide approved review accounts through App Store Connect securely, describe provider flows and moderation. Do not use fabricated engagement or an unaudited production bypass. Review mode is not currently implemented. Keep local mocks out of the submitted service.
9. TestFlight matrix: devices/OS17-current, poor connectivity/reconnect, permissions denied, OTP expiry, Keychain/session expiry, photo HEIC/JPEG/PNG processing, VoiceOver, large type, Reduce Motion, deletion/export, blocked/unmatched history, push routing and StoreKit lifecycle. Record outcomes; none of these native checks ran in the original Linux environment.
10. After approval, use a phased release, health/abuse/cost dashboards, on-call and rollback criteria. Tag the verified commit and publish honest release notes.
