# Deploy and recover

Local setup is verified separately from hosted deployment. Nothing has been deployed by this task. Terraform and deployment workflows are supplied but have not run against an account.

1. Create separate staging/production Cloudflare resources and protected GitHub environments. Require human reviewers for production and restrict allowed branches/tags. Keep ANVAYA_STAGING_ENABLED unset until staging is configured.
2. From infrastructure/cloudflare run `terraform init`, then `terraform plan -var account_id=YOUR_ACCOUNT -var environment=staging`. Review before `terraform apply`. Store state in an access-controlled encrypted remote backend; state is not a backup. The configuration provisions D1, private R2 and event/DLQ queues. R2 public bucket access must stay disabled. Durable Objects are provisioned by Wrangler migrations.
3. Export nonsecret resource outputs as CLOUDFLARE_ACCOUNT_ID, D1_DATABASE_ID, R2_BUCKET_NAME, EVENTS_QUEUE_NAME, DLQ_NAME, ADMIN_PUBLIC_ORIGIN, API_HOSTNAME and APPLE_BUNDLE_ID. Supply a least-privilege Cloudflare API token securely. Run `node infrastructure/scripts/render-wrangler.mjs staging` at repository root. It rejects missing values and example.invalid defaults and writes ignored configuration with LOCAL_MODE=false.
4. Provision provider secrets as described in providers.md. Confirm Access MFA and backend role bindings. Test signed adult attestations, provider failures and actual photo moderation before inviting real users.
5. Back up first: `npx wrangler d1 export anvaya-staging --remote --config .wrangler/deploy.staging.json --output /tmp/anvaya-before.sql`. Immediately encrypt the export and remove plaintext. Restrict decrypt keys separately from deployment access. Never attach plaintext databases to public CI artifacts.
6. Apply: `npx wrangler d1 migrations apply anvaya-staging --remote --config .wrangler/deploy.staging.json`. Then `npx wrangler deploy --config .wrangler/deploy.staging.json`. Repeat with independently provisioned production only after staging validation and protected approval.
7. Admin: in apps/admin run `npx opennextjs-cloudflare build`, configure actual API/admin hostnames in an ignored deployment config and `npx opennextjs-cloudflare deploy --env staging`. OpenNext compatibility must pass with the locked Next.js version before release. Keep the local admin bypass false. Access terminates MFA before requests reach the app; API independently validates the assertion.
8. Smoke-test HTTPS health, OTP, verified-adult activation, media moderation, discovery, reciprocal match, live/offline chat, blocking/reporting, Access roles, provider retries, notification opt-outs and sandbox renewal/refund. Confirm no synthetic accounts exist. Only then enable products and schedule a controlled TestFlight rollout.

The deployment workflow includes encrypted pre-migration artifacts (AES-256 using BACKUP_PASSPHRASE supplied as a GitHub Secret), a migration and a Worker deploy. The example retention is one day, not an adequate long-term backup policy. Production requires an audited backup store with jurisdiction-approved retention, key rotation and recovery drills. Action logs must never contain dumps or credentials.

Forward-only additive migrations 0001–0003 are used. No destructive rollback is supplied because it would erase live records. Roll back application code only to a version compatible with the current schema using `wrangler rollback` after reviewing deployment IDs. For database recovery, stop writes, decrypt backup in a secure workspace, restore into a NEW D1 database, verify counts/constraints/invariants, replay approved later writes if possible, and change the binding through a reviewed deployment. Rehearse in staging. Never import over a live database blindly.

R2 recovery needs encrypted private-object replication/versioned backups and deletion propagation, not merely a D1 export. A photo row alone cannot reconstruct deleted bytes. Dead letters require operator review with limited evidence access and a bounded replay procedure; do not replay notifications or paid actions blindly.

Release: tag an audited commit after checks and protected rollout, publish notes with schema/API changes and external verification results. Tags/releases/App Store submission remain manual until credentials and signing are configured.
